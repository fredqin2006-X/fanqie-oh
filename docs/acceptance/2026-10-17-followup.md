# 2026-10-17 续验与发布条件检查

运行环境仍为 API 26 x86_64 模拟器，未连接 HarmonyOS 6.1 / API 23 ARM64 真机。原安卓页面、组件和资源继续复用，UI 源码校验无新增差异。本次没有 GitHub 建仓、推送或 Release；用户要求的发布前提尚未满足。

## 原界面的数据流程

本节通过 HDC 操作已安装的原应用页面和系统 Picker，不由测试扩展直接写入书架或进度。

- 从书架右上菜单“导入图书”进入系统选择器，选择此前通过系统保存选择器生成的公开 195 字节 TXT；书架出现该书。
- 打开后显示“第一章 原版界面”及公开正文；点击右侧翻至“第二章 离线阅读”，显示第二章正文。
- 返回书架、杀进程、重新启动；书架保留该书，显示第 2 章 / 50%；打开后仍显示第二章正文与 50% 进度。这验证本地文件和进度持久化；本次没有禁用网络，不能据此记为完整断网验收。
- 从“我的 → 设置 → 数据 → 备份与恢复”导出，系统选择器保存 JSON 成功。原页面报告 0 条收藏、1 条在线进度、0 集已看标记，排除 2 条本地书籍相关记录。
- 再次通过系统选择器打开该 638 字节 JSON，预览数量和排除数量与导出一致。确认合并后报告新增 0 条、保留已有进度 1 条，未复制本地书籍记录。

结论：本机导出/重新选择/预览/重复合并和 TXT 重启续读通过。Android 设备导出文件的跨设备往返、缺失项恢复、损坏备份拒绝与真实断网仍待验。没有清空已有用户数据来构造通过结果。

## TTS 提前切章缺陷与修复

原阅读器启动本地书系统朗读后，两章在不到一秒内相继完成。原生日志表明当时收到的是 `CompleteResponse.type=0`（合成结束），适配层却向 Dart 发出 `done`，Dart 随即停止上一段并切章。

[华为接口说明](https://developer.huawei.com/consumer/cn/doc/harmonyos-references-V13/hms-ai-texttospeech-V13)和已安装 SDK 声明均规定：`type=0` 为合成结束，`type=1` 为播报结束。现仅在 `type=1` 时发出 `done`，保留同一请求以接收稍后的实际播报完成回调。不修改原阅读/听书 UI。

修复包：`20261016T201315702Z-8f1432`，x86_64 debug，显式 acceptance 入口。包内 min/target `60100023`，debug=true，仅 x86_64 原生库；覆盖安装成功，既有书架和进度保留。

复测证据：

- 固定中文短句：开始后一秒扩展状态只有 `start`；原生日志在 04:14:46.289 回调 type=0，04:14:50.301 才回调 type=1；随后扩展得到 `start,done`，shutdown 成功。
- 原书架进入公开本地书，从原阅读器“听书”启动系统朗读。一秒后仍显示第一章且为播放中；第一章 type=0 / type=1 分别为 04:15:25.182 / 04:15:29.587，第二章为 04:15:29.858 / 04:15:32.859。两章均等待播报完成再衔接，结束后迷你播放条停在第二章。
- 受影响的 `system_tts_test`、`audio_playback_scope_test`、`audio_listening_boundaries_test` 共 13 个 Dart 测试通过。实际原生时序用于覆盖这次 ArkTS 缺陷，主机测试本身不证明系统 TTS 播报。

此前仅凭 start/done 得到的 TTS“完成”证据已被本次缺陷否定；以上为修正后的证据。声音听感、长篇分块、后台/锁屏、暂停恢复与音色差异仍待验。

正常 `lib/main.dart` 的 ARM64 release 包已同步修复并重建，记录 `20261016T201654062Z-a2855b`；37,978,878 字节，SHA-256 `67dc918a4f7cc836480f8fa64cb3690b7c72c41aa02f6fa8aa368db5056da2d3`。手动核实 debug=false、min/target `60100023`、仅 ARM64 的三份动态库；包内 Rust/C 核心摘要与此前核实的 strip 后源码产物一致。此包未签名、未运行于 ARM64 真机。

## 可复现文档夹具

`python tools/make-document-fixtures.py local-reports/document-fixtures` 生成公开两章 EPUB、UTF-16LE/GB18030 TXT 和无效 EPUB/JSON；固定 ZIP 时间并输出摘要。EPUB spine 顺序刻意与 ZIP 顺序不同。它们不含参考书籍、真实备份或用户数据。

本轮通过 HDC 打开系统浏览器获取这些本地夹具的动作被自动审批以 `blocked by policy` 拒绝，没有提供具体原因。未继续该动作。夹具生成成功不计为系统选择器的 EPUB/编码异常验收。临时 HTTP 服务和专用反向端口已停止/移除。

## 仍阻止正式发布的条件

- 真实短剧 HEVC 在当前模拟器解码失败；合成 H.264 成功不替代真实短剧通过。
- API 23 ARM64 真机、匹配的研发签名/profile、覆盖安装及 G1–G6 完整退出门槛缺少证据。
- 原界面静态复用已核对，双端同规格截图、全部功能、锁屏/控制中心/耳机/蓝牙及异常/长时验收仍未完成。

因此尚未执行用户有条件授权的 GitHub 建仓与 v1.0.0 发布。下一轮先检查可用设备，再按未验项继续；不能把内部未签名 HAP 标记为完整交付。
