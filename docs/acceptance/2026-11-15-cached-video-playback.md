# 默认关闭边看边缓存与鸿蒙缓存播放修复

日期：2026-11-15。

## 问题与源码定位

用户反馈鸿蒙端部分已缓存剧集偶发无法播放，并要求边看边缓存默认关闭。
本轮通过源码和可控测试确认以下缺陷；没有连接用户设备复现原先失败的剧集。

- 自动缓存未配置时默认往后下载 5 集。缓存面板开启开关也使用同一个默认常量，直接改成 0 会导致开关无法开启。
- 鸿蒙原生播放器只在密钥非空时建立 CENC 解密通道。明文缓存的 `file://` 地址直接赋给 AVPlayer；AVPlayer 的本地独立文件应通过打开的文件描述符以 `fd://` 传入。本机 SDK 的 `@ohos.multimedia.media.d.ts` 中 AVPlayer.url 声明也列明此约定。
- 缓存 URI 直接拼接路径，路径里的空格、`#` 和 `%` 没有编码。
- 播放页只检查文件存在，没有核对实际字节数与完成记录；空文件、截断或长度异常的文件仍会被选中。
- 本地源起播失败后的静默重试和手动重试仍优先选中同一文件，刷新在线地址不能真正绕过坏缓存。下一集预热失败也有同一问题。
- 离线记录缺少独立密钥条目时被视作空密钥，可能把加密字节交给明文播放路径。

## 修改

- 自动缓存默认值设为 0；用户主动打开时使用独立的 5 集初始档位。保留已经主动保存的设置。
- 明文缓存先还原本地路径，再只读打开独立文件描述符供 AVPlayer 使用；退出、切集或切换软解时关闭，处理离开页面后文件才打开的竞态。软解使用还原后的本地路径；加密缓存保留原来的 CENC 通道。
- 使用 `Uri.file()` 生成缓存播放地址。
- 播放前核对文件类型、正数大小及完成记录中的字节数；无效文件返回在线取流路径。
- 在页面会话内记录失败的本地源，联网重试时绕过该源；断网时仍允许重试完整的本地缓存。首帧前沿用有限静默重试，播放中途失败后的手动重试保持续播位置。预热失败同样生效。
- 缺失密钥条目不再冒充明文流；兼容旧格式明确保存的空密钥。
- 回退过程保留已有缓存文件和记录。
