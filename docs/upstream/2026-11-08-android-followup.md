## Issue #1 原因与修正

旧 `ListeningSession.followArmed` 初始为 false，播放开始和打开阅读页都未自动打开跟随；即使允许跟随，也要手动点定位按钮。这与问题截图中的阅读位置落后、跟随按钮未启用一致，是源码层面的原因分析，未声称在用户设备重现。

- 开始/恢复播放、打开正在朗读的书时启用跟随；手动翻页暂停跟随，并可回到“原进度”。
- 使用句级时间轴、段落范围和 cue 索引定位当前页，支持跨章跟随与章节完成状态。
- 固定录音版本发布关联原著的书/章别名，阅读页按别名匹配，避免专辑 ID 与原著 ID 不同造成高亮、翻页失效。
- 鸿蒙原生播放器接收 `startPositionMs`，在 AVPlayer/软件播放器准备完成、开始播放前应用恢复位置；越过时长则从头播放。

## 共享功能与鸿蒙边界

本轮同时合入新版主题、书架分组、书旗书源、AI 阅读、后端兼容、阅读书签/查找、正文缓存和播放器画质/全屏行为。书架删除本地书时先持久清理分组归属，再执行文件删除。

鸿蒙保留 HUKS 不可导出根密钥；AI 凭据使用受命名空间限制的 AES-GCM 密文，根丢失、认证失败或损坏时拒绝换根并保留数据。AI 请求没有接入 Android 前台服务，不能承诺鸿蒙后台长任务继续执行。音频仍只开放已实现的系统变速引擎；同步 C 算法测试不等于鸿蒙新增 WSOLA 引擎。
